## Разделение режимов

- `wheel/coach.html` — прежний **офлайн-сценарий**, без Telegram SDK и сетевых вызовов, с отдельным добровольным сохранением выбранного итога.
- `wheel/miniapp-coach.html` — **отдельный экспериментальный Mini App клиент** с Telegram SDK и опциональным серверным API. По умолчанию запросы невозможны: `wheel/miniapp-coach-config.js` содержит `apiOrigin: ""`.
- Yugatneo_BOT `/api/v1/miniapp/coaching` — серверный детерминированный сценарий, **без вызова генеративного ИИ**, с валидацией Telegram HMAC initData на каждом запросе. По умолчанию `MINIAPP_COACHING_ENABLED=false`. В production/неизвестных средах блокируется независимо от флага.

## Ход субъекта и минимизация данных

1. Страница открывается без чтения сохранённых баллов и без загрузки внешнего Telegram SDK.
2. Только нажатие **«Подключить Telegram SDK»** загружает сторонний скрипт. Пользователь должен знать, что скрипт, исполняемый в origin сайта, потенциально может получить доступ к существующему localStorage.
3. Выбор основного колеса и луча из статического каталога; доступна оценка `null` — «Не передавать оценку». Любую сохранённую оценку можно подставить только после отдельного нажатия.
4. Отдельные обязательные подтверждения совершеннолетия и согласия на серверную обработку. Самоподтверждение **не является проверкой возраста**.
5. По кнопке «Начать» отправляются `wheel_id`, `ray_id` (непосредственно индекс вида `r0`), `score` (0–10 либо `null`), `mode`, согласия. Никакие соседние оценки, заметки, текст опросника, история или имена людей не включаются в запрос автоматически.
6. На каждом следующем ходе пользователь отправляет только один ответ через `Authorization: tma <signed initData>`. Сырые ответы не сохраняются в серверном состоянии и не передаются модели; сообщения, отображаемые локально, могут быть очищены.
7. При удалении клиент ждёт подтверждения сервера; при сбое честно сообщает, что удаление не подтверждено. Текущая серверная сессия истечёт за 20 минут.
8. При конфликте шага (409) клиент запрашивает текущий статус и **не пересылает личный ответ повторно автоматически**.

## Конфигурация staging (не активирована)

На выделенном **HTTPS staging-домене** с изолированным origin и проверенными скриптами нужно:
- Развернуть Yugatneo_BOT с `APP_ENV=staging`, `MINIAPP_COACHING_ENABLED=true`, Telegram BotFather токеном исключительно в защищённом серверном окружении. Не ставить флаг на публичном сервере.
- Указать **ровно один проверенный origin** Mini App в серверном `MINIAPP_COACHING_ALLOWED_ORIGINS=https://your-staging-ui.example`. Без пути, конечного слеша и подстановочных символов. Отсутствующий или неверный список не разрешает CORS.
- В отдельной копии статического клиента установить `WheelMiniAppConfig.apiOrigin` в origin staging API, например `https://your-staging-api.example`; **не** включать реальные ключи или Telegram initData в JS, URL, логи или storage.
- Настроить HTTP CSP клиента: текущий прототип имеет `connect-src https:` для конфигурируемого стенда; перед тестированием реальных чувствительных данных нужно заменить это на конкретный origin API, включая проверку Telegram SDK, ограничение сторонних скриптов и отдельное доменное размещение.
- Зарегистрировать Mini App в Telegram для проверенного staging origin; ручное тестирование реального WebView пока НЕ выполнено.
- Сопоставить правила хранения логов, резервных копий и соответствие применимому закону. Обработку чувствительных психологических/медицинских данных не открывать без независимого аудита.

**Не рекомендуется использовать общий `https://yugatn.github.io` как origin для обработки чувствительных диалогов:** разные репозитории на GitHub Pages могут разделять один браузерный origin и localStorage. Лучше выделенный изолированный домен, без других пользовательских страниц.

## Проверки

- `node wheel/tests/miniapp-coach-browser.cjs`: Playwright Chromium, синтетический Telegram SDK и имитация staging API; проверяет отсутствие запросов без действий субъекта, локальные баллы только по кнопке, передаваемый минимальный контекст, DOM-безопасность, удаление и выключенное состояние по умолчанию.
- Yugatneo_BOT: `pytest tests/test_miniapp_coaching.py` проверяет подпись, границу субъектов, отказ, ограниченные индексы лучей, CORS, удаление, TTL и отсутствие сохранения сообщений.
- Testbed **не подтверждает** реальную подпись в Telegram, сетевую защиту хостинга, клиническую пригодность или приватность всей цепочки.
- Команды CI и итоги GitHub нужно проверять на окончательных SHA.
