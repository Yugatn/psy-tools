## Разделение режимов

- `wheel/coach.html` — прежний **офлайн-сценарий**, без Telegram SDK и сетевых вызовов, с отдельным добровольным сохранением выбранного итога.
- `wheel/miniapp-coach.html` — **отдельный экспериментальный Mini App клиент** с Telegram SDK и опциональным серверным API. По умолчанию запросы невозможны: `wheel/miniapp-coach-config.js` содержит `apiOrigin: ""`.
- Yugatneo_BOT `/api/v1/miniapp/coaching` — серверный детерминированный сценарий, **без вызова генеративного ИИ**, с валидацией Telegram HMAC initData на каждом запросе. По умолчанию `MINIAPP_COACHING_ENABLED=false`. В production/неизвестных средах блокируется независимо от флага.

## Ход субъекта и минимизация данных

1. Страница открывается без чтения сохранённых баллов и без загрузки внешнего Telegram SDK.
2. **На общем GitHub Pages и любых ненастроенных доменах Telegram SDK заблокирован.** Кнопка активируется лишь при совпадении текущего изолированного HTTPS-origin с `WheelMiniAppConfig.uiOrigin` и валидной конфигурации. Тогда только добровольное нажатие загружает сторонний SDK; его права на localStorage этого конкретного домена остаются техническим риском, требующим аудита.
3. Выбор колеса и луча из статического каталога; доступна оценка `null` — «Не передавать оценку». При отдельном нажатии читается **только ключ выбранного колеса**, а не всё хранилище. `localStorage` другого домена, включая исходный GitHub Pages, недоступен на изолированном Mini App; там оценку следует ввести вручную. Будущий экспорт/импорт или синхронизация требуют отдельного явного согласия.
4. Отдельные обязательные подтверждения совершеннолетия и согласия на серверную обработку. Изменение колеса, луча, оценки или режима сбрасывает согласие; перед отправкой нового контекста его необходимо подтвердить заново. Самоподтверждение **не является проверкой возраста**.
5. По кнопке «Начать» отправляются `wheel_id`, `ray_id` (непосредственно индекс вида `r0`), `score` (0–10 либо `null`), `mode`, согласия. Никакие соседние оценки, заметки, текст опросника, история или имена людей не включаются в запрос автоматически.
6. На каждом следующем ходе пользователь отправляет только один ответ через `Authorization: tma <signed initData>`. Сырые ответы не сохраняются в серверном состоянии и не передаются модели; сообщения, отображаемые локально, могут быть очищены.
7. При удалении клиент ждёт подтверждения сервера; при сбое честно сообщает, что удаление не подтверждено. Текущая серверная сессия истечёт за 20 минут.
8. При конфликте шага (409) клиент запрашивает текущий статус и **не пересылает личный ответ повторно автоматически**.
9. По отдельной кнопке «Удалить все мои серверные сессии» клиент отправляет `DELETE /sessions` с проверенной Telegram-подписью и только после подтверждения. Отказ сервера или сбой соединения **не представляется успешным удалением**. Оценки локального колеса при этом не затрагиваются.

## Конфигурация staging (не активирована)

На выделенном **HTTPS staging-домене** с изолированным origin и проверенными скриптами нужно:
- Развернуть Yugatneo_BOT с `APP_ENV=staging`, `MINIAPP_COACHING_ENABLED=true`, Telegram BotFather токеном исключительно в защищённом серверном окружении. Не ставить флаг на публичном сервере.
- Указать **ровно один проверенный origin** Mini App в серверном `MINIAPP_COACHING_ALLOWED_ORIGINS=https://your-staging-ui.example`. Без пути, конечного слеша и подстановочных символов. Отсутствующий или неверный список не разрешает CORS.
- В отдельной копии статического клиента задать **оба** параметра: `WheelMiniAppConfig.uiOrigin="https://your-staging-ui.example"` (совпадает с текущим браузерным origin) и `WheelMiniAppConfig.apiOrigin="https://your-staging-api.example"` (точный origin API). Любые пустые, HTTP, не совпадающие или GitHub Pages UI origins оставляют сетевой режим закрытым. **Не** включать токен бота или Telegram initData в JS, URL, логи или storage.
- В репозитории клиентская CSP теперь содержит **`connect-src 'none'`**, поэтому одного изменения конфигурации недостаточно для сетевых запросов. Для выделенной копии staging **после ревью** заменить на конкретный разрешённый API origin (`connect-src https://your-staging-api.example`), ограничить внешний Telegram SDK по политике скриптов и обеспечить выделенный домен. Тестовый Chromium-контур подменяет CSP **только в синтетическом ответе**, не в файле репозитория.
- Зарегистрировать Mini App в Telegram для проверенного staging origin; ручное тестирование реального WebView пока НЕ выполнено.
- Сопоставить правила хранения логов, резервных копий и соответствие применимому закону. Обработку чувствительных психологических/медицинских данных не открывать без независимого аудита.

**Общий `https://yugatn.github.io` явно запрещён в клиентском коде Mini App**: разные репозитории на GitHub Pages имеют общий браузерный origin и потенциально разделяют localStorage. Для пилота необходим действительно отдельный домен, без посторонних пользовательских страниц и сторонних скриптов.

## Проверки

- `node wheel/tests/miniapp-coach-browser.cjs`: Playwright Chromium, синтетический изолированный HTTPS UI origin, подставной Telegram SDK и имитация staging API. Проверяет отсутствие запросов до согласия, чтение только одного ключа колеса, повторное согласие при изменении контекста, блокировку SDK на GitHub Pages, минимальный передаваемый контекст, DOM-безопасность, подтверждение/отказ удаления одной и всех сессий. CSP раскрывается только в тестовом HTML-ответе.
- Yugatneo_BOT: `pytest tests/test_miniapp_coaching.py` проверяет подпись, границу субъектов, отказ, ограниченные индексы лучей, CORS, удаление, TTL и отсутствие сохранения сообщений.
- Testbed **не подтверждает** реальную подпись в Telegram, сетевую защиту хостинга, клиническую пригодность или приватность всей цепочки.
- Команды CI и итоги GitHub нужно проверять на окончательных SHA.
