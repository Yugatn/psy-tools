## Что добавлено

- `wheel/coach.html`: доступный по ссылке из хаба и результатов каждого из 14 существующих колёс самостоятельный диалог. Никакой новый диагностический луч не создаётся.
- `wheel/coach-engine.js`: детерминированная модель в браузере; список ровно тех хранилищ, которые уже используются существующими колёсами; безопасная обработка `null` / `0` (отсутствующая оценка не становится числом); выбор любого луча без навязывания низкой оценки.
- `wheel/coach-ui.js`: явно запрашивает доступ к локальным оценкам; явное согласие перед сессией; вопросы по одному, пропуск, отмена, выводы субъекта; запись только после отдельного подтверждения.
- `wheel/tests/coach-engine.test.cjs`: изолированные тесты 13 типов колёс, детальной иерархии, отсутствующих оценок, конечного автомата.
- `wheel/tests/coach-browser.cjs`: Chromium-тест локальной приватности, согласия, пользовательского текста как текста, отсутствия внешних запросов и невидимости чужих данных между независимыми профилями.
- `.github/workflows/wheel-coach.yml`: автоматические проверки для PR.

## Принципы

1. Человек — субъект, а не результат теста. Любая числовая оценка — субъективное наблюдение, которое можно пересмотреть.
2. Три добровольных режима: `reflection` (5 вопросов), `reframe` (5 вопросов), `coaching` (6 вопросов). Вопросы не притворяются индивидуальными ответами ИИ.
3. Начальная версия **не использует генеративную модель**, не делает психотерапию, не ставит диагнозов и не обещает терапевтической эффективности.
4. Отрицательные и альтернативные гипотезы равноправно исследуются; недопустимо требовать позитивного переосмысления проблемы.
5. Нет фонового чтения: страница не перечисляет локальные колёса до нажатия «Показать мои локальные оценки».
6. Ответы держатся в JS-памяти текущей вкладки, не записываются и не передаются автоматически. Копирование осуществляется только по нажатию. Завершение/уход со страницы удаляет данные из памяти, насколько это возможно в контролируемом коде; браузерные инструменты, история устройства или вредоносный скрипт не входят в гарантию.
7. «Сохранить в заметке» — **отдельный осознанный выбор** с подтверждением; сохраняется только выбранный, доступный для редактирования итог в существующем ключе `Improvements` конкретного луча. Уже сохранённые цели не изменяются, исходные заметки дополняются.
8. Изоляция пользователей ограничена границей браузерного профиля. Один браузерный профиль может использоваться разными людьми: записи доступны в этом случае. Обязателен явный privacy notice. См. `wheel/PRIVACY_MODEL.md` в PR #4.
9. Нет API-ключей в HTML/JS и нет вызовов backend; локальная страница запрещает сетевые `connect` через CSP. Для **первой загрузки статических файлов GitHub Pages требуется доступ к серверу**; истинный offline-first PWA сейчас не реализован.
10. Кнопка «Мне нужна помощь сейчас» завершает обычную сессию и предлагает связь с реальными экстренными службами/людьми. Примитивные правила диалога не умеют выявлять кризис, не заменяют квалифицированный мониторинг.

## Ограничения и следующие этапы

- `Yugatn/Yugatneo_BOT` уже имеет `app/services/coaching_session.py`, `app/services/wheel_domain.py`, `app/miniapp_wheel_api.py` и каталог вопросов; следующее направление — согласовать единый протокол. **Ничего не синхронизируется с ботом автоматически**.
- Защищённый облачный ИИ потребует аутентификацию, per-user авторизацию, согласие на передачу конкретного контекста, серверные API-ключи, правила удаления и retention, отдельную проверку безопасных ответов.
- Не использовать публичный анонимный вызов LLM из GitHub Pages; не обещать «AI therapy».
- Клинические методы, шкалы, психотерапия и потенциальное воздействие на уязвимых пользователей требуют независимой профессиональной оценки, не подтверждаются функциональными тестами.
- Реальные iOS Safari, Android Chrome и Telegram WebApp ещё не пройдены, если нет отдельных отчётов. Chrome/Chromium smoke tests не заменяют эти испытания.
- Дополнительная privacy-hardening и структура кабинета находятся в другом черновике PR #4. Новая ветка создана от main, чтобы не смешивать неподтверждённые изменения.

## Научная/этическая опора

American Psychological Association, advisory «Use of generative AI chatbots and wellness applications for mental health» (2025): https://www.apa.org/topics/artificial-intelligence-machine-learning/health-advisory-chatbots-wellness-apps

Методы психологического сопровождения в ИИ должны быть прозрачны и не представляться психотерапией без доказательств, профессионального надзора и соответствующих разрешений.
