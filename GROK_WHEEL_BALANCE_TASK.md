## Полное совершенствование существующих колёс баланса

Репозиторий: https://github.com/Yugatn/psy-tools

## 0. Главная цель

Улучшить **существующие** колёса баланса до единого, устойчивого и функционально согласованного приложения.

### КРИТИЧЕСКОЕ ОГРАНИЧЕНИЕ

**НЕ создавать новые колёса, новые сферы, новые уровни или новые смысловые разделы.**

Работать только с уже существующими колёсами и их текущей иерархией.

Главный принцип:

> **Любое существующее детальное колесо должно быть функциональным аналогом основного колеса, а не урезанной отдельной страницей.**

Функции должны быть общими по архитектуре, но данные и контекст — изолированными.

## 5. КРИТИЧЕСКОЕ: состояние «не оценено»

Исправить модель состояния.

Должны существовать два разных состояния:

- `unrated`;
- реальная оценка `0..10`.

**5 не является состоянием «не оценено».**

Для нового колеса:
- лучи существуют;
- шкала существует;
- значения отсутствуют;
- интерфейс явно показывает, что оценки ещё нет;
- среднее не считается по неоценённым лучам;
- минимум не становится искусственно равным 0;
- зона внимания не считает неоценённый луч реальным минимумом;
- история не записывает фиктивные оценки.

После оценки одного луча:
- только этот луч становится оценённым;
- остальные остаются `unrated`.

При полном заполнении:
- статистики считаются по реальным значениям.

Существующие сохранённые пользовательские значения не удалять.

Проверить desktop, мобильный Safari, Android Chrome, resize, DPR/Retina и Telegram WebApp.

Не должно быть ситуации:

> «колесо открывается, но лучей нет».

## 8. Deep-link и навигация

Использовать стабильный URL-контракт:

`parent`, `ray`, `label`, `trail`, `back`.

Проверить:

1. Main → sphere.
2. Sphere → detail.
3. Detail → next detail.
4. Detail → parent.
5. Parent → main.
6. Refresh на каждом уровне.
7. Прямое открытие deep-link.
8. Browser Back.
9. Telegram Back.
10. URL после нескольких переходов.

Исправить потерю параметров, неправильный последний экран, двойное URL encoding, неправильный scroll и открытие данных соседнего уровня.

Навигация не должна зависеть от хрупких предположений о порядке страниц.

---

## 9. Storage namespace

Каждый уровень должен иметь детерминированный уникальный namespace.

Например:

`wheelBalanceV3:<wheelId>:<parent>:<trail>`

Точный формат выбрать после аудита существующей совместимости.

Требования:

- main не смешивается с detail;
- health не смешивается с work;
- разные rays не смешиваются;
- разные уровни одного ray не смешиваются;
- journal/history/goals/reflections также контекстны;
- импорт не записывает данные в соседний уровень.

Не уничтожать старые данные.

При изменении ключей:
- реализовать миграцию;
- сохранить старый формат;
- миграция идемпотентна;
- повторная миграция не портит данные.

---

## 10. LocalStorage resilience

- пустое значение;

Нормализация не должна превращать отсутствие оценки в реальную оценку.

## 14. Сброс

Reset current wheel сбрасывает только текущее колесо.

Не затрагивает:
- parent;
- siblings;
- другие levels.

Очистка целей/истории требует отдельного явного подтверждения.

Не удалять глобальные настройки и чужие namespaces.

## 15. Export / Import

JSON содержит минимум:

- app;
- schema/version;
- wheelId;
- parent;
- trail;
- level;
- values;
- rated/unrated;
- goals/improvements;
- reflections;
- journal/history, если экспортируются.

Импорт:
- проверяет schema;
- проверяет wheel identity;
- не смешивает уровни;
- нормализует значения;
- не превращает unrated в 0/5;
- не ломает существующие данные без подтверждения;
- не исполняет пользовательский текст как HTML/JS.

Старые версии поддерживать через migration layer, если возможно.

## 16. Безопасность

## 25. Критерии приёмки

Работа считается выполненной только если:

A. Ни одно существующее колесо не потеряло функциональность.

B. Детальные колёса имеют тот же UX и функциональный набор, что и основное, с адаптацией контекста.

C. У каждого уровня собственные данные.

D. Новое колесо действительно пустое до первой оценки.

E. Unrated не равен 0 и не равен 5.

F. На каждом колесе корректно видны лучи.

G. Deep-link не теряет context.

H. Refresh не меняет выбранный уровень.

I. Reset одного уровня не уничтожает соседние данные.

J. Import/export не смешивает колёса.

K. Старые пользовательские данные не уничтожаются.

L. Проект продолжает работать как статический GitHub Pages.

M. Не добавлены новые колёса.

N. Issues не закрываются автоматически.
