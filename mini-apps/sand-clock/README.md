# Песочные часы · PSY-TOOLS Mini App

Автономный адаптивный обратный таймер для мобильного браузера и Telegram WebView. **Главный критерий качества: визуальный объём песка вычисляется из того же остатка времени, что и цифровой таймер.** Число кадров анимации не влияет на ход часов.

## Возможности v1.0

- Интервал от **1 секунды до 24 часов** (целые часы, минуты и секунды).
- Готовые интервалы 30 секунд, 1, 3, 5, 10, 15, 25, 30, 45, 60, 90 минут.
- «Начать», «Пауза», «Продолжить», «Повторить», «Сброс», в том числе после завершения таймера.
- Песочные часы как собственная векторная SVG-иллюстрация, поддерживающая адаптивное оформление и Telegram-переменные цвета.
- Доля уже прошедшего времени, прогресс-бар и цифровой обратный отсчёт; при завершении пустая верхняя и заполненная нижняя колба.
- Необязательные короткий сигнал Web Audio и вибрация (если браузер поддерживает).
- Локальное сохранение состояния и момента окончания. При повторном открытии состояние вычисляется с учётом прошедшего по часам устройства времени, а не с числом сработавших таймерных callbacks.
- Сниженная нагрузка в простое: `requestAnimationFrame` запускается только при активном отсчёте и видимой странице.
- Режим `prefers-reduced-motion` отключает декоративную анимацию песочной струи, но сохраняет фактический уровень песка и цифровое время.

## Математическая связь уровня песка и времени

Две камеры SVG моделируются как симметричные **усечённые треугольники** (трапеции на изображении) высотой 131 условная единица: ширина 16 у горлышка и 176 на широком конце. Объём на двумерной схеме приближён площадью заполнения при одинаковой толщине стекла.

Для нормализованной доли прошедшего времени `p = clamp(1 - remaining / duration, 0, 1)` нижний объём равен `p`, а верхний `1 - p`. Относительная высота слоя `h` определяется **не линейно**, а по площади трапеции:

- Верхняя камера (считая от горлышка вверх): `(16*h + 80*h*h) / 96 = 1-p`, поэтому `h = (sqrt(256+30720*(1-p)) - 16)/160`.
- Нижняя камера (считая от плоского дна вверх): `(176*h - 80*h*h) / 96 = p`, поэтому `h = (176-sqrt(30976-30720*p))/160`.

Результат: при 50% времени **площади** песка в верхней и нижней колбах равны, хотя их высоты различаются. Декоративная анимация отдельных песчинок и струи лишь иллюстрирует поток; она не задаёт количество песка. SVG обновляется из фактического `snapshot()` каждый кадр.

Дедлайн при старте записывается как `Date.now() + remainingMs`. Пауза фиксирует остаток, продолжение создаёт новый дедлайн; после сворачивания/пропуска кадров остаток снова определяется относительно дедлайна.

**Точность и ограничения:** `Date.now()` зависит от системного времени. Ручная перестановка часов устройства, специфические настройки энергосбережения или приостановка фоновой страницы могут изменить момент срабатывания сигналов. Текстовый остаток и графика синхронизированы между собой, но это не лабораторный хронометр и не серверный будильник. Web Audio/вибрация возможны только при открытой странице и разрешениях платформы, **фоновое системное уведомление при закрытом Mini App не гарантируется**.

## Приватность

`localStorage` содержит только длительность, статус, оставшееся время и момент завершения. Никаких личных аккаунтов, координат, дат рождения, личных данных Telegram и сетевых API не используется. При общем профиле браузера настройки видны другим пользователям этого профиля. Чувствительных значений сюда вводить не требуется.

## Проверка

```bash
node --test tests/sand-clock.test.cjs
node --check mini-apps/sand-clock/timer-engine.js
```

Тесты проверяют реальные миллисекунды независимо от частоты кадров, валидацию настроек, математическую пропорциональность площадей и времени, завершение после перезагрузки, паузу/продолжение, SVG-элементы и синтаксис формы. Дополнительно последовательность действий проверена в изолированном макете DOM: 05:00 → спустя 2,5 минуты 02:30 и 50% заполнения → пауза сохраняет 02:30 → завершение 00:00, верхняя колба пуста, нижняя заполнена.

Автоматические GitHub Actions настроены, но их **фактический проход**, доступность GitHub Pages и реальные испытания в iOS Safari/Android/Telegram WebView надо проверить отдельно.
