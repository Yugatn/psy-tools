## Что реализовано

- Ввод **даты, времени, исторического смещения UTC**, широты и долготы места рождения. Места-пресеты (Москва, Стокгольм, Лондон, Бангкок, Дананг, Нью-Йорк) подставляют **только координаты**: историческое UTC-смещение не угадывается по текущей часовой зоне города.
- При отсутствии точного времени разрешён расчёт положений на **12:00 UTC** выбранного дня с явным предупреждением; **ASC, MC и дома не строятся**, чтобы не выдавать произвольный час за действительное время рождения.
- Геоцентрические астрономические положения по истинной эклиптике даты: Солнце, Луна, Меркурий, Венера, Марс, Юпитер, Сатурн, Уран, Нептун, Плутон.
- **Тропический** зодиак, 12 знаков по 30°, градусы внутри знака, оценка ретроградного движения по изменению долготы за сутки.
- **ASC и MC** — вычисляются из местного звёздного времени, широты, долготы и среднего наклона эклиптики. Это приближённая, не топоцентрическая астрологическая реализация. В высоких широтах у некоторых конфигураций обычное понятие восходящего градуса требует дополнительных соглашений; широта интерфейса ограничена ±89°.
- **Равнодомная система от ASC** с 12 куспидами через 30°; **MC не обязательно совпадает с 10-м куспидом**. Плацидус и иные системы в данном MVP не реализованы.
- Аспекты по абсолютной разнице геоцентрических долгот: соединение (8°), секстиль (5°), квадрат (6°), тригон (6°), оппозиция (8°). Орбисы — пользовательская договорённость программы, не измерение психологического эффекта.
- Адаптивный SVG-круг знаков, планет и аспектов, таблица планет, отдельная панель ASC/MC, экспорт круга в SVG, копирование текста, системное меню «Поделиться», печать в PDF. Работает на мобильном экране без сборки, настраивается как Telegram Mini App.

## Улучшение v1.1 · историческое время и неопределённость Луны (19.11.2026)

Добавлен независимый браузерный модуль [`timezones.js`](./timezones.js) и [тесты](../../tests/natal-timezones.test.cjs). **Главная задача — не подменять историческую зону рождения её современным UTC-смещением.**

В форме имеются два режима:

- **«Ввести UTC-смещение вручную»** — исходное поведение полностью сохранено. Полезно, если известны часы и документально подтверждённое смещение, а исторические правила браузера недостаточны.
- **«Вычислить по исторической зоне IANA»** — выбирается идентификатор зоны (например, `Europe/Minsk`, `Europe/Moscow`, `Asia/Yakutsk`, `Europe/Stockholm`). Приложение через `Intl.DateTimeFormat.formatToParts()` находит точный момент UTC и смещение, учитывая исторические правила часового пояса, содержащиеся в браузере. Внешних запросов не выполняется.

В Беларуси при выборе страны **предлагается `Europe/Minsk`**. Для России **нельзя автоматически выводить зону по долготе**: исторические и региональные различия требуют проверенного идентификатора IANA. Поэтому российская форма изначально сохраняет ручной режим, а в автоматическом режиме пользователь самостоятельно выбирает зону из списка. Указанные в справочнике «UTC+3» или «UTC+7» — ориентир **современного** смещения, а не время рождения.

Для местного времени в дни перевода часов новая логика явно различает:

1. **Однозначное время** — отображаются вычисленное смещение UTC и абсолютный момент.
2. **Дважды встречающееся местное время (DST fold)** — в интерфейсе предлагаются два возможных момента. Пока не выбран один из них, карта не строится.
3. **Несуществующее местное время (DST gap)** — показывается ошибка, а UTC не подменяется догадкой. Можно проверить дату и часы либо переключиться на ручной режим.

Контрольные случаи: `Europe/Minsk` — 15.01.2010 UTC+2, 15.07.2010 UTC+3, 15.01.2020 UTC+3; `31.10.2010 02:30` — два момента; `28.03.2010 02:30` — пропуск. `Europe/Moscow` — `26.10.2014 01:30` повторялось. Разные браузеры могут иметь разные версии базы IANA; **эта функция не является независимым архивом юридических часовых постановлений**. Неопределённость нужно уточнять по документам о рождении и историческим источникам.

Усовершенствован `chart.js` (v1.1). Теперь движок может принимать точное UTC-смещение **в секундах** от IANA-модуля (для некоторых исторических зон минуты недостаточны), сохраняя исходный ручной формат `±HH:MM` для совместимости. При неизвестном времени рождения вместо ASC и домов показывается отдельный **диапазон положения Луны за 00:00–23:59 UTC** выбранной даты. Это условная граница по UTC, не точный интервал суток в месте рождения; следовательно, она **не позволяет определить истинное положение Луны без времени и часовой зоны**.

Приложение не создаёт, не сохраняет и не отправляет персональную натальную карту без явного действия пользователя. Текстовый экспорт содержит фактический момент UTC, указанную зону IANA (если выбрана) и диапазон Луны в случае неизвестного времени.

Проверка проекта:

```bash

```

Сохранён отдельно существующий код справочников и расчётного движка, изменения носят обратно совместимый характер. UI доступен в браузере и подготовлен для Telegram WebView, но **проверка реальных мобильных устройств, статуса Pages и завершения GitHub Actions требует отдельного наблюдения**.

## Астрономический движок: лицензия и точность

В каталоге `vendor/` включена **Astronomy Engine 2.1.19**, библиотека Дональда Кросса (Don Cross), лицензия **MIT**, исходник зафиксирован по коммиту:

`https://github.com/cosinekitty/astronomy/tree/865d3da7d8112bbc7911238052c6af4aaf877181/source/js`

В начале `vendor/astronomy.browser.min.js` сохранён полный текст лицензии MIT. Библиотека не требует внешнего API, оплаты эфемерид, доступа к личному Telegram-профилю и отправки данных на сервер.

**Астрономические координаты ≠ астрологические предсказания.** Библиотека вычисляет положения Солнца, Луны и планет. Знаки, дома и аспекты — отдельная историческая геометрическая система отображения. Утверждения о характере, судьбе, здоровье и совместимости не имеют научно подтверждённой предсказательной точности.

### Формулы и решения

В ручном режиме UTC вычисляется из указанного местного времени и **явного** часового смещения: `UTC = local time − UTC offset`. Не используем текущий UTC-сдвиг автоматически для исторической даты: переходы на летнее/зимнее время, административные изменения, региональные реформы часовых поясов и ранние годы могут сделать такой сдвиг неверным. Для исторических дат пользователь должен проверить часовой пояс отдельно.

Планеты вычисляются с `Astronomy.GeoVector(body, utc, true)` и `Astronomy.Ecliptic(vector).elon`; применяется коррекция аберрации света там, где она поддерживается библиотекой. Положение Луны геоцентрическое (не топоцентрическое).

Местное звёздное время: `LST = 15 * Astronomy.SiderealTime(utc) + longitude`. Для вычисления ASC используется восточная точка пересечения эклиптики с математическим горизонтом, для MC — эклиптическая долгота меридиана. Наклон эклиптики рассчитывается через приближение среднего наклона по Юлианским столетиям от J2000. Использование среднего наклона при кажущемся звёздном времени создаёт небольшую дополнительную погрешность. **Это не реплика Swiss Ephemeris и не сертифицированный профессиональный астрологический расчёт.**

Система домов — Equal Houses (равнодомная, первый куспид совпадает с ASC, каждый следующий +30° по долготе). Приближённый ретроградный индикатор основан на разнице положения за 12 часов до и после, не на дифференциальном аналитическом решении.

## Как включить в Telegram

1. Создать или выбрать бота в [@BotFather](https://t.me/BotFather).
2. В настройках бота настроить **Main Mini App** или соответствующее приложение по <https://core.telegram.org/bots/webapps>.
3. Указать HTTPS-адрес `https://yugatn.github.io/psy-tools/mini-apps/natal-chart/` при подтверждённой доступности страницы в GitHub Pages.
4. Открыть через кнопку/меню Telegram, проверить дату, мобильный ввод времени, координаты и экспорт SVG.
5. Токены бота **не нужны в клиентском JavaScript и не должны попадать в публичный GitHub**.

Запуск без Telegram из обычного браузера поддерживается. Telegram SDK подключается только если адрес содержит параметры Web App, вызывает `ready()` и `expand()`; API оплаты, отправки персональных данных в бот или регистрации не используется.

## Конфиденциальность

Никакие данные рождения не сохраняются в localStorage или cookies приложения; веб-страница не делает API-запросы для вычисления эфемерид. При использовании системного меню «Поделиться» информация передаётся адресату только по пользовательскому действию. Сам Telegram/браузер может иметь собственную телеметрию или историю посещений — приложение не контролирует платформу. Не публиковать чужие данные рождения без согласия.
